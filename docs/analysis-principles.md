# 특허 분석 공통 원칙

이 저장소의 도구와 프롬프트가 함께 따르는 작업 원칙입니다.
청구항 분해와 대비 표기에 관한 세부 기준은 [청구항 분석 공통 기준](claim-analysis-standard.md)을 따릅니다.

## 1. 사실과 근거

- 확인된 사실과 분석적 추론을 구분해서 씁니다.
- 특허 원문, 요약문, 사용자가 제시한 기술 설명, 분석자의 의견을 서로 구분합니다.
- 특허번호, 공개일, 등록 상태, 청구항 문구를 지어내지 않습니다.
- 확인되지 않거나 모호한 내용은 추정으로 채우지 않고 `분석 보류`로 표시합니다.
- 기업 정보, 제품, 특허의 법적 상태, 정책처럼 바뀔 수 있는 정보는 최신 자료로 확인하고 출처를 밝힙니다.
- 기술적으로 비슷하다는 이유만으로 침해·무효·등록 가능성을 단정하지 않습니다.

## 2. 결과물 작성

- 사용자가 정한 출력 형식과 분량을 우선합니다.
- 복잡한 내용은 항목별로 나누고, 필요하면 표·목록·단계별 절차를 씁니다.
- 요약은 간결하게 하되, 기술적 차이를 판단하는 데 필요한 구성요소와 인과관계는 빼지 않습니다.
- 외국어 특허나 기술자료도 분석 결과는 한국어로 쓰고, 근거가 되는 원문 표현은 원어 그대로 둡니다.
- 한 번 요청받은 형식을 이후의 모든 작업에 무조건 적용하지 않습니다.

## 3. IPC/CPC 분류와 검색 키워드

- 독립항과 발명의 핵심 구성을 기준으로 IPC/CPC 후보를 제안하고, 코드마다 관련 구성요소와 근거를 적습니다.
- 코드의 세부 수준은 실제 분류체계와 관련 특허로 확인합니다.
- 검색 키워드는 한국어와 영어를 함께, 가능한 한 명사형으로 씁니다.
- 일반적인 산업 분야 단어보다 핵심 부품·구조·기능·작용 용어를 우선합니다.
- 동의어, 상위 개념, 하위 개념, 표현 변형을 함께 고려합니다.

## 4. 선행기술 대비와 특허성 검토

### 입력

대상 특허의 청구항, 선행 특허·공개문헌, 선행기술조사 보고서, 거절이유통지서·심사관 의견, 필요하면 명세서와 도면.

### 출력

- 청구항별 구성요소 대비표 (대상 문헌과 선행문헌의 대응 구성)
- 동일·유사 구성과 차이 구성
- 선행문헌에 명시된 내용과 추론한 내용의 구분
- 결합 논리와 결합 동기 검토
- 차이 구성의 기술적 효과와 과제 해결 기여
- 신규성·진보성 검토 의견, 필요하면 의견서·반박 논리 초안

### 원칙

- 선행기술에 기재되지 않은 구성을 기재된 것처럼 쓰지 않습니다.
- 여러 문헌을 결합해 논할 때는 "각 구성이 따로 알려져 있다"는 사실과 "통상의 기술자가 실제로 결합할 동기가 있다"는 판단을 구분합니다.
- 법률적 결론은 자료의 범위와 관할 법제에 따라 달라질 수 있으므로, 분석 지원과 최종 법률 판단을 구분합니다.

## 5. FTO(침해 회피) 청구항 대비

- 대응 여부 표기는 [청구항 분석 공통 기준](claim-analysis-standard.md)의 O/△/X를 따릅니다.
- X(대응 없음)는 자료로 분명할 때만 쓰고, 애매하면 △를 씁니다.
- 분석 결과 목록에는 실제로 청구항 대비를 한 특허만 올리고, 목록 순서를 분석 순서와 맞춥니다.

## 6. Excel 특허 데이터 요약

- RAW DATA 시트를 바탕으로 특허별 요약을 만듭니다.
- 요약의 근거는 대표청구항 → 발명의 명칭 → 요약 순으로 우선합니다.
- 결과는 기술분야, 해결과제, 해결수단을 중심으로 정리합니다.
- 원본 데이터의 특허 식별정보와 요약 결과의 대응 관계를 유지합니다.
- 대표청구항이 없으면 발명의 명칭이나 요약으로 보완하되, 데이터에 없는 내용을 채우지 않습니다.

## 7. 자동화 결과 검증

- 자동화 결과가 원본 데이터와 정확히 대응하는지 확인합니다.
- 누락 데이터, 중복 특허, 형식 불일치, 잘못된 분류를 점검합니다.
- 프롬프트나 코드를 바꿀 때는 같은 입력으로 바꾸기 전후 결과를 비교합니다. 이 저장소에서는 `tests/`의 회귀 테스트와 GitHub Actions가 이 역할을 합니다.

## 8. 프롬프트 작성

- 프롬프트에는 역할과 분석 범위, 필수·선택 입력, 단계별 처리 절차, 출력 형식, 예외 처리, 근거·검증 원칙을 넣습니다.
- 분량은 5,000자 이내를 기본으로 합니다.
- 특정 AI 서비스 전용 용어를 쓰지 않아, Claude와 ChatGPT 어느 쪽에서 실행해도 같은 결과가 나오도록 씁니다.
- 공개 저장소에는 API 키, 비밀번호, 개인정보, 고객·회사 기밀, 공개 권한이 없는 특허 자료를 올리지 않습니다. 예시는 직접 만든 가상 자료를 씁니다.
