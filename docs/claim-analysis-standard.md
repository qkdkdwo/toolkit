# 청구항 분석 공통 기준

이 문서는 아래 결과물이 함께 따르는 기준입니다. 용어와 표기가 같아야 도구의 출력을 프롬프트의 입력으로 그대로 이어 쓸 수 있습니다.

- 청구항 분해·시각화 도구 (`tools/claim-visualizer`)
- 5. 청구항 구성요소 분석기 프롬프트 (`prompts/5_claim-component-analyzer`)
- 6. 핵심특허 청구항 분석기 프롬프트 (`prompts/6_core-patent-claim-analyzer`)

## 1. 역할 분담

| 구분 | 분해·시각화 도구 | 5. 구성요소 분석기 | 6. 핵심특허 청구항 분석기 |
|---|---|---|---|
| 방식 | 문장 규칙 기반, AI 미사용 | AI 해석 | AI 해석 |
| 실행 위치 | 브라우저 안 (외부 전송 없음) | AI 서비스 | AI 서비스 |
| 담당 | 1차 분해, 인용관계, 검토용 표 | 기능·역할 해석, 과제 기술 대비 | 전체 청구항 대비표, 공통점·차이점, 전략 의견 |
| 비교 대상 입력 | 없음 | 과제 기술 설명 (필수) | 기업 보유 기술 (필수), 발명의 설명 (권장) |
| 검토의견 범위 | 해당 없음 | 기술 대비만 (7장 A) | 전략 의견 포함 (7장 B) |

## 2. 청구항 구조 분해 (4단계)

| 구분 | 내용 | 예 (한국어) | 예 (영어) |
|---|---|---|---|
| 전제부 | 발명의 대상, 종속항에서는 인용 청구항 | ~에 있어서, / 제1항에 있어서, | A device, / The device of claim 1, |
| 연결부 | 권리범위 해석에 영향을 주는 연결 표현 | ~를 포함하는, ~것을 특징으로 하는 | comprising, consisting of, wherein |
| 본문 | 실제 구성요소·단계와 그 관계 | 온도 센서부; 신호 처리부; … | a sensor; a processor; … |
| 종결부 | 청구 대상을 특정하는 마무리 | 웨어러블 체온 측정 장치. | . |

- 한국어·일본어는 청구 대상이 문장 끝(종결부)에 오고, 영어·중국어는 문장 앞(전제부)에 옵니다.
- 전제부/특징부 2단계 방식과의 대응: **특징부 = 연결부 + 본문**.

## 3. 구성요소 추출

구분 기호의 강도에 따라 나눕니다.

| 강도 | 기준 | 처리 |
|---|---|---|
| 강 | 줄바꿈, 번호, 단계 표시, 세미콜론(; / ；) | 원칙적으로 분리. 단, 앞 구성의 수식·기능·조건 설명이면 병합 |
| 보조 | 콜론(: / ：) | 뒤에 목록이 이어질 때 분리 |
| 약 | 쉼표(, / 、 / ，) | 쉼표만으로 분리하지 않음. 뒤에 새 명사구나 단계가 시작될 때만 분리 |

- 장치 청구항은 부품·모듈·수단을, 방법 청구항은 단계를 하나의 구성요소로 봅니다.
- 다음 표현은 원문 그대로 보존하고 표시합니다: 및/또는, 중 적어도 하나, 내지, 복수의, 각각, 상기, and/or, at least one of, a plurality of, consisting of.
- 경계나 명칭이 불분명한 구성요소는 `(원문 불명확)`으로 표시하고 임의로 보완하지 않습니다.
- 발명의 설명을 참고해 의미를 해석했으면 `(발명의 설명 참조)`로 표시합니다.

### 구성요소 기호

- 구성요소는 소문자 알파벳 `a, b, c …`로 표시하고, 청구항이 바뀌면 `a`부터 다시 시작합니다.
- 다른 청구항의 구성을 가리킬 때는 `1a`, `2b`처럼 청구항 번호를 붙입니다.
- 카드형 출력의 배지는 `구성 a`, `구성 b`로 씁니다.

## 4. 연결관계 표기

- `A → B` 는 **B가 A를 인용하거나(상기 A), A와 연결·작용 관계에 있음**을 뜻합니다.
- 화살표 방향은 청구항에 먼저 기재된 구성(A)에서 그 구성을 참조하는 뒤 구성(B)으로 향합니다.
- 관계의 성격을 알 수 있으면 괄호로 짧게 적습니다. 예: `온도 센서부 → 신호 처리부 (신호 수신)`

## 5. 청구항 유형 주의

청구항의 표제(종결부 또는 전제부의 청구 대상)와 본문 구성이 맞지 않으면 `⚠ 청구항 유형 주의`로 표시합니다.

- 표제는 방법인데 본문에 단계가 없는 경우
- 표제는 장치·시스템인데 본문이 단계로만 이루어진 경우

## 6. 검토 표기 (O/△/X)

구성요소별로 비교 대상(과제 기술, 기업 보유 기술 또는 선행기술)에 대응하는 구성이 있는지를 **기술적으로** 표시합니다.
O/△/X 자체는 침해·무효·권리범위 판단이 아닙니다.

| 표기 | 짧은 표기 | 기준 |
|---|---|---|
| O | 사실상 동일 | 비교 대상 자료에 대응 구성이 명확히 있고 실질적으로 같음 |
| △ | 일부 대응 | 유사하나 구조·방식·목적에 차이가 있음, 일부만 대응함, 또는 자료만으로 확인이 어려움 |
| X | 대응 없음 | 자료를 확인한 결과 대응 구성이 없거나 무관함이 분명함 |

- 판단이 어려우면 X 대신 △를 씁니다.
- 각 표기에는 근거(대응 구성, 차이점 또는 자료 위치)를 함께 적습니다.
- HTML 출력의 배지 클래스는 `mark-o`, `mark-t`(△), `mark-x`로 통일합니다.

## 7. 검토의견

### A. 기술 대비 (도구, 5번 프롬프트)

- 구성요소별 O/△/X를 바탕으로 3~5문장으로 씁니다.
- 쓰는 내용: 기술적 유사점·차이점, 비교 대상에 참고하거나 적용할 수 있는 기술적 시사점.
- 쓰지 않는 내용: 권리해석, 침해 판단, 회피설계, 무효 가능성, 법적 자문.
- 단정하지 않습니다. 예: "~로 보임", "~참고 가능성 있음".

### B. 전략 의견 (6번 프롬프트)

- 핵심특허 분석의 목적상 침해 리스크(문언·균등), 회피설계 방향, 기업 기술 개량 방안에 대한 의견을 허용합니다.
- 모든 의견은 공통점·차이점 대비 결과와 청구항·발명의 설명 원문을 근거로 하며, 근거가 없는 단정은 하지 않습니다.
- 결과물에는 반드시 다음 고지를 넣습니다: **"본 결과는 기술 대비와 전략 검토를 위한 분석 지원 자료이며, 최종 법률 판단이 아닙니다."**

## 8. 도구 → 프롬프트 연계

도구에서 내려받은 CSV(열: 청구항, 구분, 기호, 구성요소, 원문, 기능·관계, 연결관계, 검토, 메모)를 프롬프트에 청구항 원문과 함께 넣으면, 프롬프트는 이 분해 결과를 출발점으로 삼아 기능 해석과 검토를 이어갑니다.
